# 文档维护规则

## 目标

`.codex` 是项目知识的可导航整理层。文档应帮助开发者和编码代理快速理解现状、定位代码并安全修改。

根目录 `AGENTS.md` 只保留仓库级约束和知识库导航，所有项目描述、产品设计、结构、功能和排障内容统一放入 `.codex`。

## 目录职责

| 目录 | 内容 |
| --- | --- |
| `rules/` | 工程约束、安全要求、发布流程和文档维护规则 |
| `structure/` | 仓库结构、技术架构、数据模型和模块边界 |
| `features/` | 面向用户的功能行为、实现状态和限制 |
| `troubleshooting/` | 可复现问题的原因、诊断步骤和恢复流程 |

## 内容原则

- 使用中文说明，命令、API、字段名和文件名保留原文。
- 区分“当前实现”和“设计目标”，不能把未来计划写成已实现能力。
- 事实优先于概括。涉及命令、事件、字段、默认值和文件路径时，应尽量给出具体名称。
- 文档应链接相关源码或 `.codex` 中的其他文档，避免复制大段源代码。
- 不记录密钥、Token、个人内容库数据或其他敏感数据。
- 与根目录 `AGENTS.md` 冲突时，以 `AGENTS.md` 为最高优先级项目约束。
- 不在根目录新增或恢复项目设计、结构说明、功能说明和历史问题文档。

## 更新时机

以下变化需要同步更新文档：

- 新增、删除或重命名 Tauri 命令。
- 新增或修改事件名称、窗口标签、快捷键默认值。
- 修改 `Settings`、`ContentEntry` 字段或持久化位置。
- 修改确认粘贴、取消、内容库保存或设置保存流程。
- 修改生产构建、签名、安装或权限要求。
- 新增平台支持或改变已支持平台的范围。

## 推荐更新路径

1. 功能行为变化：更新 `features/` 对应文档。
2. 命令、事件、窗口或模块变化：更新 `structure/architecture.md`。
3. 字段或存储变化：更新 `structure/data-model.md`。
4. 构建、安全或权限变化：更新 `rules/security-release.md`。
5. 新增文档或改变导航：更新 `MOC.md`。
6. 根目录 `AGENTS.md` 只更新导航入口或仓库级约束，不复制具体项目知识。

## 链接检查

提交前检查：

- `MOC.md` 中所有链接可打开。
- 文档中的相对路径以自身所在目录为基准。
- 迁移文档使用正确的相对路径回指 `MOC.md`、源码和同目录文档。
- 文件名和标题使用一致术语，例如 `Settings`、`ContentEntry`、`main`、`settings`、`content`。
