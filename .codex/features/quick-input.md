# 快速输入

## 目标

用户在任何应用中按全局快捷键唤出输入窗口，输入内容后确认，QuickInput 将内容写入剪贴板、切回原应用并模拟粘贴。

## 入口

- 默认全局快捷键 `Alt+Space`。
- 托盘菜单“打开输入框”。
- 单实例重复启动时，主窗口获得焦点。

## 输入窗口

主窗口标签为 `main`，默认尺寸 720 × 240，支持：

- 无边框、透明、置顶。
- 拖动顶部工具栏移动窗口。
- 从右下角调整大小。
- 选择纯文本或 Markdown 模式。
- 显示字符数。
- 清空、取消和确认。
- 底部显示当前快捷键提示。
- 可在设置中开启纯净输入模式，只显示输入区域。
- 可调整输入框字体大小，范围为 12px 到 32px。

## 内容模式

| 模式 | 编辑体验 | 确认后写入剪贴板 |
| --- | --- | --- |
| 纯文本 `plain` | 普通 `textarea` | 纯文本 |
| Markdown `markdown` | 输入区加实时 HTML 预览 | 优先使用前端渲染 HTML，Rust 侧可兜底渲染 |

Markdown 预览有约 150 ms 的输入防抖。Rust 渲染器支持标题、列表、代码块、行内代码、粗体、斜体和安全链接。

代码模式已移除。旧设置中的 `default_mode = "code"`、旧内容库或迁移片段中的未知模式都会按纯文本处理。

默认内容模式在设置保存后立即应用；取消或确认关闭输入窗口后，下一次输入会重新使用该默认模式。

## 默认快捷键

| 操作 | 默认值 | 作用域 |
| --- | --- | --- |
| 唤起 | `Alt+Space` | 系统全局 |
| 确认 | `Alt+Enter` | 主输入窗口 |
| 取消 | `Escape` | 主输入窗口 |
| 清空 | `Alt+Backspace` | 主输入窗口，当前固定值 |
| 打开内容库 | `Alt+R` | 系统全局 |
| 打开设置 | `Alt+S` | 系统全局 |

快捷键可通过设置修改，但清空快捷键当前没有设置项。

## 确认流程

1. 前端检查内容是否为空。
2. 调用 `confirm_input`，传入 `text`、`mode`、`attempt_id`、可选的 `rendered_html` 和 `action`（`paste` 或 `paste_and_enter`，省略为 `paste`）。
3. 后端再次检查内容是否为空。
4. macOS 上检查辅助功能权限。
5. 保存当前剪贴板文本和 HTML 快照。
6. 按模式写入新内容。
7. 隐藏主窗口。
8. 等待窗口消失，并激活唤起前的前台应用。
9. 等待快捷键松开（最多 2 秒），检查目标应用仍在前台，模拟 `Command+V` 或 `Ctrl+V`。
10. 等待 480 ms；本次动作是 `paste_and_enter` 时，再等待快捷键松开并检查目标 PID，然后模拟一次不带修饰键的普通 Enter，再等待 80 ms 让按键事件生效。
11. 按设置恢复剪贴板，发送 `paste-complete`，再根据设置保持窗口关闭或重新打开。

隐藏后等待 400 ms、激活后等待 150 ms，位于 `src-tauri/src/lib.rs`；粘贴后等待 480 ms、按键释放与焦点检查由 `src-tauri/src/confirmation.rs` 编排。主输入框与内容库共享粘贴操作锁，避免并发改写剪贴板。

### 可选的粘贴并发送快捷键

设置“启用粘贴并发送快捷键”（`paste_and_send_enabled`）默认关闭，旧配置缺少该字段时保持关闭。

| 操作 | 关闭时 | 开启时 |
| --- | --- | --- |
| 确认快捷键（默认 `Option/Alt+Enter`） | 只粘贴 | 只粘贴 |
| `Shift+Enter` | 保留原有换行行为 | 粘贴后模拟一次普通 Enter |
| `Enter` | 换行 | 换行 |
| 点击“确认” | 只粘贴 | 只粘贴 |

- 不注册新的系统全局快捷键；只影响主输入窗口，内容库直接粘贴不会追加 Enter。
- 开启后底部提示和占位文字立即更新；纯净模式不显示底栏，但快捷键仍有效。
- 输入法组合输入和键盘长按重复事件不会触发确认；粘贴流程结束前不能再次确认。
- 后端也验证开关，关闭时拒绝 `paste_and_enter` 请求，不依赖前端作为安全边界。
- “发送”仅代表模拟回车；目标应用必须使用 Enter 发送，不能保证内容已经粘贴或消息已经发出。
- PID 检查只能确认目标应用，不能识别同一应用内不同聊天或输入框；没有应用白名单或自动重试。

## 确认后的窗口状态

- `keep_open_on_confirm = false`：调用确认命令成功后立即清空隐藏窗口中的输入区和模式，下次唤起不会闪现上一轮内容。
- `keep_open_on_confirm = true`：前端立即清空输入区；后端在粘贴流程结束后重新显示并聚焦主窗口。
- 粘贴失败：后端发送带 `attempt_id`、`message` 和 `pasted` 的 `paste-error`；`pasted = false` 时恢复该次文本和模式，重新显示窗口供检查和重试。
- 已尝试粘贴后回车失败或焦点变化：`pasted = true`，仅显示“已尝试粘贴，未完成回车”的提示，不恢复旧文本、不自动重试，以免重复粘贴或重复发送。
- 异步流程结束后发送 `paste-complete`（含 `attempt_id`），前端才解除工作状态；保持打开时也必须等回车处理完成后再重新显示窗口。

## 取消流程

点击取消或按 `Escape` 时：

1. 调用 `cancel_input`。
2. 隐藏主窗口。
3. 激活唤起前记录的前台应用。
4. 前端清空输入内容。

`cancel_input` 接收 `text` 和 `mode` 参数，但当前后端不使用它们。

## 失败与限制

- 空内容不会进入确认粘贴或内容库保存流程。
- macOS 未授予辅助功能权限时，确认流程返回错误并提示授权 `/Applications/QuickInput.app`。
- 粘贴模拟失败时，目标应用可能已经重新获得焦点，主窗口会重新显示供重试。
- 恢复剪贴板失败不会回滚已经完成的粘贴。
- 设计文档要求点击输入框外部取消，但当前主窗口代码只监听窗口聚焦变化，没有看到外部失焦时调用 `cancel_input` 或隐藏窗口的显式逻辑；修改前应按实际运行行为验证。
