# QuickInput 产品设计

> 一个跨平台的全局快速输入工具：任何应用里，按快捷键弹框输入，确认后自动粘贴到光标位置。
>
> 本文由根目录原 `DESIGN.md` 迁移整理，保留产品需求和设计基线。当前实现状态以[产品路线](product-roadmap.md)和[快速输入](quick-input.md)为准。

## 1. 核心流程

```
任意 App 聚焦输入状态
       │
(1) 按全局快捷键 (默认 ⌥Space)
       ▼
(2) 浮层输入框出现（默认屏幕居中，可在设置中改为光标附近）
       ├─ 输入文本
       ├─ 切换 Plain / Markdown 模式
       │
(3) 确认 (⌘Enter)            取消 (Esc / 点击框外)
       │                            │
       ▼                            ▼
  自动切回原 App               退回原 App
  模拟 ⌘V / Ctrl+V 粘贴        不做任何操作
  恢复原剪贴板
```

## 2. MVP 范围

### Phase 1 — MVP 核心闭环

- 全局快捷键触发 / 确认 / 取消
- Plain 纯文本模式输入与粘贴
- 剪贴板保存 / 恢复
- 切回原 App + 模拟粘贴
- 菜单栏图标 + 基础设置面板（快捷键录制、默认位置、开机自启）
- 跨平台：macOS + Windows

### Phase 2 — 格式增强

- Rich 富文本（B / I / U / 颜色 / 字体）
- Markdown 实时预览与渲染粘贴
- 图片拖入 / 粘贴支持

### Phase 3 — 体验打磨

- 内容库 / 搜索
- 重要内容手动保存
- 快捷键冲突检测
- 动画过渡
- 自动更新

## 3. UI 设计

### 浮层输入窗口

- 无边框、圆角 16px、轻阴影
- 磨砂玻璃背景，自动适配深色 / 浅色
- 默认 720×240，可拖拽调整，记住上次尺寸
- 位置：默认屏幕居中，可在设置中选择光标附近

### 编辑器核心

- 大面积文本编辑区（MVP 用 textarea，后续升级为富文本编辑器）
- 顶部工具栏（MVP：模式切换、清空、确认、取消）

```
[Plain ▼]          [🗑] [123字] [✓ 确认] [✕ 取消]
```

### 设置窗口

- 快捷键：触发 / 确认 / 取消，支持按键录制，带冲突检测
- 通用：默认模式、窗口位置偏好、开机自启、恢复剪贴板开关
- 外观：主题（跟随系统 / 深色 / 浅色）、字体、透明度滑杆
- 内容库：手动新增、搜索、编辑和单条删除

## 4. 剪贴板流程

确认时执行严格顺序，保证不丢数据：

> 以下是产品设计阶段的流程基线。当前实现的等待时间、窗口隐藏顺序和输入清理顺序见[快速输入](quick-input.md)。

```
1. 读取当前系统剪贴板内容，保存到内存
2. 根据当前模式构建目标格式数据写入剪贴板
3. 激活之前的前台 App
4. 等待 100ms 让 App 完成聚焦
5. 模拟 ⌘V (macOS) / Ctrl+V (Windows)
6. 等待 300ms 让粘贴完成
7. 恢复第 1 步保存的原剪贴板内容
8. 关闭浮层窗口
```

## 5. 技术架构

- **技术栈**：Tauri 2 (Rust 后端 + Web 前端)，实现跨平台
- **前端**：Vite + 原生 HTML / CSS / JS（MVP 保持轻量）
- **后端职责**：
  - 全局快捷键注册（`tauri-plugin-global-shortcut`）
  - 剪贴板读写（`arboard`）
  - 前台 App 抓取与切换
  - 模拟粘贴快捷键
  - 窗口显隐管理

## 8. 新增需求（v0.2 迭代）

### 交互修复

- Esc 必须能取消并隐藏输入框；点击输入框外部也应自动取消。
- 底部快捷键提示间距统一，保持视觉对齐。
- 点击确认发送后，输入框内容必须清空，下次唤起不能残留上次内容。

### 内容库（长期记忆）

- 每次确认发送的内容自动记录，保存在本地文件中。
- 记录持久化，不因应用退出或 macOS 重启丢失。
- 内容库独立页面展示，入口包括输入框底部按钮和菜单栏托盘菜单。
- 每条记录支持重新编辑后再次使用。
- 支持单条删除、勾选多条删除、全选后删除、清空全部。
- 内容库条目删除后不再恢复。

### 开发顺序

1. 修复 Esc / 外部点击取消
2. 修复提示间距
3. 修复确认后清空输入
4. 实现内容库后端持久化与命令
5. 实现内容库独立页面
6. 接入输入框与托盘入口
